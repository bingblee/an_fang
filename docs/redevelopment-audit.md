# 安放重开发前项目审查报告

版本：1.0

审查日期：2026-09-07
审查对象：当前仓库 anfang-life-copilot、现有产品文档、自动化测试和已实现页面

## 1. 结论

当前项目已经是一套可试用的个人事项管理 MVP，而不是概念原型。它实现了“输入 → 保存 → AI 整理 / 本地降级 → 进入队列 → 用户处理 → 提醒 / 复盘”的主要闭环，并在认证、用户隔离、SQLite 迁移、附件安全、主题、PWA 和响应式布局方面有较完整的工程基础。

重开发不应简单复制页面。最重要的工作是把当前隐含的领域边界显式化，补齐异步处理、提醒触达、来源追溯和 AI 可撤销机制。建议继承产品方向和数据分层思想，重做后台任务、提醒和详情体验。

### 优先级

- **可继承**：捕获优先、原始 Capture 与 Item 分层、状态与出现时间分离、话题 / 分类双组织、建议便笺与笔记本分离、多用户隔离、Web Push 基础。
- **P0 必须重做**：异步捕获任务、复盘与场景触达、来源时间线、合并确认 / 撤销、失败恢复、提醒可观测性。
- **P1 应补齐**：个人上下文设置、任务 / Capture / 笔记搜索、建议历史、通知设置、导出与数据治理、领域模块化。
- **暂缓**：自动定位、自动读取聊天、多人协作、未经确认的长期人格推断。

## 3. 当前已实现能力

### 用户和数据

- 用户名密码注册、登录、服务端会话和记住登录 30 天；
- scrypt 密码哈希、登录失败限流、Cookie 会话、请求来源检查；
- 业务表按 user_id 隔离；
- 旧 SQLite 迁移、生产 / 开发环境隔离、附件路径校验；
- 改密、退出登录、推送订阅绑定和会话撤销。

### 捕获和 AI

- 文字、链接、JPG / PNG / GIF / WebP 图片；
- Capture 在 AI 调用前落库；
- DeepSeek 文本 / 视觉解析和本地规则降级；
- 标题、备注、分类、优先级、耗时、精力、人物、场景、时间提取；
- 近期候选筛选，支持新建、补充合并、附加建议；
- 建议便笺可以复制到独立笔记本。

### 事项和体验

- 今日、稍后、等待中、进行中、待确认、笔记本；
- 精确时间、时间窗口和无时间事项的递增复盘；
- 完成、今天做、安排时间、继续放着、等待中、不再处理；
- 话题、六类固定分类、分类合集；
- 桌面侧栏、移动底部导航、PWA、Web Push、浅色和夜航深色主题。

## 4. 关键问题

| 优先级 | 问题与证据 | 影响 | 重开发建议 |
| --- | --- | --- | --- |
| P0 | app/api/captures/route.ts 在写入 Capture 后仍同步等待 DeepSeek 和建议生成，最长等待约 35 秒；前端只有 submitting 状态。 | 用户无法放心离开，移动端切后台或网络抖动会造成重复提交和失败恢复问题。 | Capture 立即返回 202，使用 Job 处理，前端显示 saved / processing / ready / failed。 |
| P0 | triggers 可以写入 time、review、context，但 lib/reminder-scheduler.ts 只查询 scheduled + scheduled_for 到期事项。 | 无时间复盘和场景触发不能形成完整的系统通知，产品承诺与实现不一致。 | 独立 Trigger Evaluator，统一处理 time、review、waiting、context 和 digest。 |
| P0 | Capture failed 只落库，没有 Capture 历史或失败恢复页面；接口文案说可在收件箱处理，但收件箱实际只展示 needsConfirmation Item。 | AI / 数据库失败时原始输入难以找回，违背保存而不是丢弃。 | 增加 Capture Inbox、重试、手动建事项、原文和图片查看。 |
| P0 | AI / 本地规则会直接把补充写入目标 Item，没有候选预览、差异、确认和撤销。 | 同名或语义相近事项可能误合并，用户很难恢复。 | 默认生成 MergeProposal，展示目标和字段差异，确认后写入版本；始终保留撤销。 |
| P0 | 数据库保留 item_sources，但事项卡只显示一个 sourceExcerpt 和最新附件，没有完整来源时间线。 | 用户无法核对哪次输入导致了哪些事实和时间变化。 | 事项详情显示全部 Capture、附件、解析版本和人工修改历史。 |
| P1 | context_facts 表存在，但没有页面、API、类型和可执行规则；Person、Habit、Preference 只在文档中。 | “理解生活”无法由用户声明、检查、撤销。 | 先做作息、勿扰、场景、人物和确认规则；逐条可查看、过期、删除。 |
| P1 | isActionable 被 schema 接收，但创建流程未使用；普通信息也可能成为待办。 | 任务池会被资料和建议请求污染。 | 明确区分 task、information、suggestion、archive。 |
| P1 | 约 1600 行逻辑集中在 components/app-shell.tsx；每次变更都刷新完整 dashboard。 | 后续增加详情、来源、上下文和搜索时，状态耦合、性能和回归成本会快速上升。 | 按 Capture、Today、Item、Later、Topics、Notebook、Settings 拆 feature；API 分页和局部 mutation。 |
| P1 | itemSelect 只返回最新建议，历史只保留计数；任务备注和完成 / 放弃历史也没有统一界面。 | 知识资产和用户修订不可见。 | 事项详情提供建议历史、版本历史、来源历史和统一搜索。 |
| P1 | API 已有 snooze action，但 UI 没有快捷入口；安排时间依赖 datetime-local。 | 移动端延后成本高，今晚 / 明天 / 周末等常用意图表达不自然。 | 提供快捷时间、时区提示和自定义时间面板。 |
| P1 | 通知只有铃铛开关，没有勿扰、渠道、设备、最近投递和失败原因。 | 用户无法建立稳定预期，也不知道为什么没收到。 | 增加通知中心和设置页。 |
| P1 | mvp-review.md 仍描述“当前是单用户应用”，但代码已实现多用户认证。 | 旧文档会误导范围、验收和迁移。 | 以本审查报告和三份重开发文档为新基线，旧文档加历史标记。 |
| P2 | 没有自助忘记密码、导出、删除账号和附件生命周期页面。 | 公网使用和隐私治理能力不足。 | 先保持安全管理员重置，再补邮箱 / Passkey / 导出删除。 |
| P2 | 链接只保存 URL，不抓取页面，也没有来源引用。 | 用户可能误以为链接内容已理解或联网核验。 | 明确 UI 仅保存链接；未来以白名单检索服务提供引用。 |

## 5. 需要继承的设计决策

1. 捕获优先，不在输入时要求复杂表单。
2. 每次输入都保留为独立 Capture，合并只建立关联，不覆盖原文。
3. 事项状态与出现时间分别管理。
4. 建议不是待办，不参加完成状态和提醒队列。
5. 用户手动修改优先于后续 AI；简单事项默认保持安静。
6. 复盘每日最多主动展示三件，避免一次性倒出积压。
7. 开发 / 生产数据隔离，开发不发送真实提醒。
8. 继承浅色自然绿灰和深色夜航视觉，避免退化为通用项目管理模板。

## 6. 重开发验收门槛

- 输入提交后 1 秒内返回已保存，AI 在后台完成；
- 模型失败时仍能查看、重试和手动处理 Capture；
- 合并有目标、差异、来源、确认和撤销；
- 精确提醒、复盘、等待检查和场景触发有统一投递记录；
- 事项详情可见全部来源、附件、AI 版本、修改和建议历史；
- 用户可查看、修改、禁用和删除个人上下文；
- Item、Capture、笔记和历史支持搜索；
- 320px、390px 和桌面无横向滚动，键盘和屏幕阅读器可操作；
- Lint、类型、单元、集成、浏览器、无障碍、安全测试和生产构建通过；
- 文档中的当前 / 计划 / 暂不实现与代码状态一致。
