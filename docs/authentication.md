# 登录与会话

安放支持多个独立账号。每个账号拥有自己的事项、话题、笔记、截图、AI 上下文和提醒订阅，登录后只能访问自己的数据。

## 初始账号

1. 第一次启动服务时，系统自动创建普通账号 `bingbing`，并在同一数据库事务中归入无归属的历史数据；该账号没有管理其他用户的权限；
2. 初始密码随机生成，保存在当前环境数据目录的 `initial-account.json` 中。默认正式路径为 `data/production/initial-account.json`，开发路径为 `data/development/initial-account.json`，文件权限为 `0600`，不进入 Git 或部署文件清单；
3. 在 `/login` 使用用户名 `bingbing` 和文件中的密码登录，进入账号页输入当前密码和新密码进行修改；成功后自动删除该账号的初始密码文件；
4. 其他用户可以从登录页进入 `/register` 自助注册，注册不会接管历史数据。

初始化有持久化完成标记，重启不会重置密码、重建账号或再次分配数据。已有账号、密码及已有归属的数据保持原样。如果升级前已存在名为 `bingbing` 的账号且仍有无归属数据，系统会停止初始化，要求服务器管理员核实归属，避免将历史私人数据授予未经确认的已有账号。

开发库与正式库相互独立，因此首次启动各自生成账号和独立密码。把正式数据刷新到开发环境时会保留全部账号、密码及初始化标记，但不复制初始明文密码文件，会删除所有正式登录会话、限流记录及推送订阅。构建不会初始化账号或修改运行数据库。

## 修改与重置密码

记得当前密码时，在账号页输入当前密码、新密码、确认新密码。用户名本身不能证明身份，不能单凭用户名修改密码。

忘记密码时，由拥有服务器本机访问权限的管理员执行：

```bash
npm run auth:reset -- --env production --username bingbing
```

命令会要求输入两次新密码，输入不回显；开发环境指定 `--env development`。也可以重置其他已有用户名。密码至少 10 位且包含字母和数字，不存在的账号不会被创建。非交互环境可通过 `--password-file /private/password.txt` 读取仅当前系统用户可读写的文件（单行密码，可带一个末尾换行），用完后由管理员删除该文件。命令不接受明文密码参数。

重置不会删除业务数据，会在事务中更新密码并撤销该账号所有会话和推送订阅，其他用户不受影响；重新登录后恢复已授权设备的推送。现有登录限流仍按原有 15 分钟窗口生效。

不再使用 `AUTH_SETUP_TOKEN`，已有环境变量不会生效。旧 `/setup`、`/recover` 页面转到登录页，对应 POST API 返回 `410 Gone`，无法创建初始账号或重置密码。

## 注册与数据归属

- 注册使用用户名和密码，不要求邮箱；用户名忽略首尾空格、大小写和全半角差异后必须唯一；
- 每位用户可以拥有相同名称的话题，但它们属于不同账号，彼此不可见；
- 升级时仅无归属记录归入系统新建的 `bingbing`，截图、来源关系和提醒随关联事项保留，已有归属记录不会转移；
- AI 只会收到当前用户的相关事项摘要和话题，不会拿其他用户的数据作为合并候选或建议上下文；
- 提醒只发送到事项所属用户当前有效会话绑定的设备。

当前版本为开放注册：任何能访问站点登录页的人都可以创建自己的隔离账号。公开部署时应配合 HTTPS、反向代理访问控制和合理的服务器资源限制；邀请制与管理员用户管理留待后续版本。

## 安全边界

- 密码通过 Node.js `scrypt` 与每个账号独立的随机盐派生，数据库不保存原文；
- 登录时生成 256 位随机令牌，数据库只保存 SHA-256 摘要；
- 勾选“记住登录”时 Cookie 最长保留 30 天；未勾选时关闭浏览器后 Cookie 消失，服务端最长保留 24 小时；
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，请求经 HTTPS 到达时增加 `Secure`；
- 页面、业务 API、附件和推送接口同时校验会话与数据归属；跨站修改请求会被拒绝；
- 同一用户名和来源连续失败 5 次后暂停登录 15 分钟；
- 修改密码会撤销该账号的其他全部会话，并为当前设备签发新会话；
- 退出时撤销当前服务端会话，前端同时取消当前浏览器的推送订阅。
- 已授予通知权限的设备会在重新登录、改密后及返回首页时恢复当前会话的推送订阅；只有服务端确认订阅成功才显示“系统提醒已开启”，自动恢复不会弹出权限请求。
- 推送仅接受 HTTPS 的 Chrome/FCM、Firefox、Safari 和 Windows 通知服务地址；拒绝自定义地址、非标准端口和带凭据的 URL，发送前也会重新校验历史订阅。
- 无有效订阅的账号不会占用提醒投递批次；失败事项等待至少 5 分钟重试，并排在尚未尝试的事项之后。

## 公网部署

不要直接把 Next.js 端口暴露到公网。使用 Caddy 或 Nginx 终止 HTTPS，并传递正确的 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto` 和客户端地址。数据库、上传目录与 `.env.local` 的系统权限只授予运行应用的系统用户。
