# 登录与会话

安放支持多个独立账号。每个账号拥有自己的事项、话题、笔记、截图、AI 上下文和提醒订阅，登录后只能访问自己的数据。

## 首次设置

1. 在服务器环境变量中配置至少 20 位的 `AUTH_SETUP_TOKEN`；
2. 打开 `/setup`，输入首次设置口令、用户名和自己的密码，创建初始账号；
3. 初始账号创建后，其他用户可以从登录页进入 `/register` 自助注册；
4. `AUTH_SETUP_TOKEN` 仍用于管理员级密码找回。不需要此能力时可以从服务器环境变量中移除，重新部署或重启后生效。

如果忘记密码，先在服务器重新配置 `AUTH_SETUP_TOKEN`，再从登录页进入“忘记密码”。重置成功会撤销所有旧会话；完成后可再次移除服务器上的口令。

开发库与正式库相互独立，因此第一次分别启动时需要各自创建初始账号。把正式数据刷新到开发环境时会保留全部账号和密码，但会删除所有正式登录会话、限流记录及推送订阅。

## 注册与数据归属

- 注册使用用户名和密码，不要求邮箱；用户名忽略首尾空格、大小写和全半角差异后必须唯一；
- 每位用户可以拥有相同名称的话题，但它们属于不同账号，彼此不可见；
- 从旧版单账号数据库升级时，已有事项、笔记、话题、截图和订阅自动归入原账号；
- AI 只会收到当前用户的相关事项摘要和话题，不会拿其他用户的数据作为合并候选或建议上下文；
- 提醒只发送到事项所属用户当前有效会话绑定的设备。

当前版本为开放注册：任何能访问站点登录页的人都可以创建自己的隔离账号。公开部署时应配合 HTTPS、反向代理访问控制和合理的服务器资源限制；邀请制与管理员用户管理留待后续版本。

## 安全边界

- 密码通过 Node.js `scrypt` 与每个账号独立的随机盐派生，数据库不保存原文；
- 登录时生成 256 位随机令牌，数据库只保存 SHA-256 摘要；
- 勾选“记住登录”时 Cookie 最长保留 30 天；未勾选时关闭浏览器后 Cookie 消失，服务端最长保留 24 小时；
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，请求经 HTTPS 到达时增加 `Secure`；
- 页面、业务 API、附件和推送接口同时校验会话与数据归属；跨站修改请求会被拒绝；
- 同一用户名和来源连续失败 5 次后暂停登录 15 分钟；
- 修改密码会撤销该账号的其他全部会话，并为当前设备签发新会话；
- 退出时撤销当前服务端会话，前端同时取消当前浏览器的推送订阅。
- 已授予通知权限的设备会在重新登录、改密后及返回首页时恢复当前会话的推送订阅；只有服务端确认订阅成功才显示“系统提醒已开启”，自动恢复不会弹出权限请求。
- 推送仅接受 HTTPS 的 Chrome/FCM、Firefox、Safari 和 Windows 通知服务地址；拒绝自定义地址、非标准端口和带凭据的 URL，发送前也会重新校验历史订阅。
- 无有效订阅的账号不会占用提醒投递批次；失败事项等待至少 5 分钟重试，并排在尚未尝试的事项之后。

## 公网部署

不要直接把 Next.js 端口暴露到公网。使用 Caddy 或 Nginx 终止 HTTPS，并传递正确的 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto` 和客户端地址。数据库、上传目录与 `.env.local` 的系统权限只授予运行应用的系统用户。
