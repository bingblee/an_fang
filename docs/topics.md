# 话题：把相关事项放在一起

## 这一版的使用方式

- 在首页输入“请创建一个关于星河项目的话题”。“主题”“专题”同样支持。这条指令只建立话题，不会变成待办。
- 也可以打开“话题 → 新建话题”，填写名称与可选描述。描述能帮助 AI 理解项目边界，例如“官网改版的设计、研发与发布”。
- 记录文字、链接或截图时，输入框下方可选择“AI 自动归类”“未归类”或指定话题。
- 打开一个话题后，输入框默认选中该话题；待处理和已完成的事项分开展示。今日、稍后页面仍按原有时间规则显示这些事项。
- 展开事项的“更多操作”即可修改所属话题，不改变时间、状态、来源、提醒或建议便笺。
- 话题支持修改名称与描述，引用它的事项标签同步更新。

## 归属与合并规则

1. 一个事项暂时只属于一个话题，也可以未归类。话题是组织层，不是另一种事项状态。
2. 手动选择优先，包括手动选择“未归类”。AI 不会在后续补充时悄悄覆盖这个选择。
3. AI 只在已提供的话题中选择，置信度至少 0.8 才采纳。没有明确归属就不分配；不会因为内容出现“工作”“项目”就强行归类。
4. AI 不可用时，仅做唯一的话题名称匹配。名称有歧义时保持未归类。
5. 同一个项目里的不同事项分别保存，不因为同话题就合并。补充时间、地点等事实仍可关联到原事项。
6. 手动选择的话题限制合并候选；AI 识别出的另一话题不能覆盖原话题的任务。已有手动未归类事项在自动补充时保持未归类。
7. 同名话题创建幂等；修改名称不允许与另一个话题重名。原有数据迁移后默认未归类，不自动重写历史内容。

## 数据与隐私

- 新增 `topics` 表，事项新增 `topic_id` 和 `topic_source`，通过外键关联；来源分为手动、AI、名称匹配。
- 原始输入仍完整保存。包含“创建话题 + 具体事项”的输入，只把具体事项交给模型整理，原文不截断覆盖。
- 调用模型时，在原有当前输入与最多六条相关事项摘要之外，最多提供 40 个话题的名称、描述和 ID；优先保留当前指定或名称匹配的话题。不会发送完整数据库。
- 本版没有自动批量重归类、话题删除、子话题或多话题标签。话题超过 40 个时，不保证每个话题都进入每次 AI 上下文；手动选择不受此限制。
- 事项与来源、话题归属、提醒触发器在一个本地事务中更新；模型网络请求不占用该事务。

## 回归检查

```bash
npm run build
npm test
```

测试启动独立 Next.js 服务、临时 SQLite 数据库与模拟模型服务；不使用真实 Key、不读取用户数据库、不发送系统通知。覆盖旧库迁移、自然语言创建、手动优先、自动归属、跨话题合并保护、截图、来源与提醒、建议及笔记副本、完成统计和本地降级。

`KEEP_TEST_DATA=1 npm test` 可以保留临时测试库，路径在测试结束时打印，用于界面复核。不要把测试库配置为正式数据目录。

## 后续可迭代

- 话题级摘要：进展、等待回复、关键风险与下一步建议。
- 人工确认后，将历史未归类事项批量收进话题。
- 话题归档与可撤销删除，保留其任务和原始来源。
- 话题量增加后，先检索候选话题再调用模型，而非固定数量上下文。
- 跨话题的生活习惯、关系和执行条件，继续作为独立的个人上下文层。
