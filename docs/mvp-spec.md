# MVP 产品需求

## 1. MVP 目标

验证最重要的产品承诺：用户随手输入一次后，系统能够可靠地保存、整理，并让事项在合适的时候重新出现。

MVP 不追求全面理解用户生活，先完成“捕获—理解—提醒—反馈”的闭环。

## 2. 核心用户故事

### 2.1 随手记录

当我突然想到一件当前无法处理的事情时，我可以发送一段文字、一张截图或一个链接，然后立即回到当前工作。

### 2.2 自动理解

系统自动识别内容中是否包含需要行动的事项，并提取：

- 事项动作；
- 工作或生活分类；
- 截止时间；
- 合适的处理时间；
- 涉及人物；
- 场景或地点；
- 前置条件；
- 紧急程度；
- 预计耗时和所需精力；
- AI 置信度。

在创建新事项前，系统先从近期未完成事项中进行本地相关性筛选。AI 判断当前输入是新事项，还是对某一事项的时间、地点、人物、备注或状态补充。只有目标明确且置信度达到阈值时才自动合并，否则保持为独立事项。

合并不会覆盖原始输入。每次输入作为独立来源保存，并共同关联到最终事项。

系统还需要区分“事实补充”和“知识补充”：

- “下午的高铁时间是 17:58”更新原事项的时间和描述；
- “查找做披萨的方法，附在买材料那件事下面”不创建新的查找任务，而是把生成结果作为建议便笺附到披萨事项；
- “今天买做披萨的材料”这类存在明显知识缺口的事项可以主动附加材料清单或做法；
- 倒垃圾、取快递等简单琐事默认不建议，避免每条事项都被 AI 扩写。

建议与正式事项分层保存。用户可以在事项上按需请求“给我建议”，后续新建议不会覆盖原始输入。建议便笺可以删除，或复制到“笔记本”长期保留；复制后事项建议继续显示，笔记副本可以独立编辑和删除，两边互不影响。这些操作都不会删除对应的原始 Capture。

### 2.3 快速确认

一般情况下只显示一行结果，例如：

> 已记录：今晚回家后找一下保修卡。

只有负责人、截止时间或提醒条件存在关键歧义时才追问。用户没有回答时仍按默认方案保存。

### 2.4 合适时提醒

MVP 支持：

- 精确时间；
- 今天、今晚、周末等时间窗口；
- 每日回顾；
- 每周回顾；
- 等待中事项的定期确认。

人物、地点和自动条件触发可以先记录，后续版本再实现完整自动触发。

### 2.5 提醒后处理

每条提醒支持：

- 完成；
- 一小时后；
- 今天晚些时候；
- 明天；
- 周末；
- 自定义时间；
- 等待某个条件；
- 放弃。

事项卡片上显示的 AI 识别时间或推荐时间可以直接修改、清除。修改后必须同时更新事项和实际提醒触发器，并保留修改前后的反馈记录。

## 3. MVP 页面

### 3.1 快速输入

- 页面主区域只保留一个明显的输入入口；
- 支持输入和粘贴文字；
- 支持拖入或粘贴截图；
- 支持链接；
- 输入完成后立刻保存原始内容，再异步执行 AI 解析。

### 3.2 收件箱

展示尚未确认、信息不足或解析置信度较低的内容。用户可以修改分类、时间、动作和提醒条件。

### 3.3 今日

分为三组：

1. 今天必须处理；
2. 适合顺手处理；
3. 有时间再做。

系统控制主动展示数量，避免把所有积压事项一次性推给用户。

### 3.4 等待与以后

- 等别人；
- 等材料或其他条件；
- 周末处理；
- 暂无明确时间；
- 以后可能想做。

没有明确提醒时间的事项必须通过周期回顾重新出现，不能永久沉底。

### 3.5 设置

MVP 只需要保存少量上下文：

- 通常的起床、工作和睡眠时间；
- 工作日和周末；
- 希望收到每日整理的时间；
- 通常方便处理生活琐事的时间；
- 通知开关。

## 4. 提醒内容规范

提醒至少包括：

```text
现在适合处理：提交报销
原因：你昨天确认已经收到发票，预计需要 10 分钟。
来源：8 月 26 日上传的聊天截图。
```

系统应避免只有“该做某事了”而没有上下文的提醒。

## 5. 基础数据对象

### Capture

保存一次原始输入：类型、原始文字、附件、链接、创建时间和来源。

### Item

AI 或用户从 Capture 中生成的事项：动作、分类、状态、优先级、耗时、精力和置信度。

### Trigger

事项重新出现的条件：精确时间、时间窗口、人物、地点、前置条件或周期回顾。

### Reminder

实际产生的提醒记录，包括提醒原因、触达时间和用户处理结果。

### Feedback

记录用户对 AI 解析和提醒的修改，例如负责人错误、提醒太早、分类错误或建议有用。

### ItemEnrichment

附在事项下方的建议、方法或清单，记录触发它的用户输入、生成模型、置信度和时间。它不是待办，不参与完成状态和提醒队列。

### NotebookNote

从建议便笺中长期保存的独立笔记副本。保存时复制标题、摘要和正文，并记录来源事项；笔记支持修改标题、摘要和正文，也可以独立删除。之后即使事项完成，笔记仍能在笔记本视图中查看。

## 6. 状态流转

```text
已捕获
  → AI 解析中
  → 待确认 / 已安排 / 等待中 / 以后处理
  → 已提醒
  → 已完成 / 已延后 / 重新安排 / 已放弃
```

## 7. MVP 暂不实现

- 自动读取全部聊天记录；
- 自动替用户发送消息或提交材料；
- 后台持续位置追踪；
- 复杂项目管理和多人协作；
- 过度复杂的积分、连续打卡和成长评分；
- 未经确认就长期保存 AI 对人物关系的推断；
- 直接微调模型。
- 把模型生成的建议冒充为实时联网搜索结果；带来源的实时检索留待后续版本。

## 8. MVP 验证指标

试用阶段优先观察：

- 从产生想法到完成输入需要多长时间；
- AI 提取出的事项有多少不需要修改；
- 有多少记录最终在合适时间重新出现；
- 提醒被完成、延后、忽略的比例及原因；
- 用户是否仍需要依赖其他地方反复记同一件事；
- 每日整理是否减少遗漏和心理负担。
