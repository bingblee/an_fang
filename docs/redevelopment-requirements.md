# 安放重开发需求文档

版本：1.0

状态：重开发基线
产品：安放（个人 AI 外部大脑）

## 1. 产品定义

安放帮助个人把临时念头、截图和链接先保存下来，再由系统负责整理、重新呈现和适度辅助执行。

核心承诺：

> 用户只需要在想到事情时告诉系统一次。此后，记住它、整理它，并在合适的时候让它重新出现，是系统的责任。

安放不是传统项目管理工具，也不是以完成率、连续打卡或积分为中心的效率工具。它要减少遗漏、心理悬挂，以及从“记得做”到“知道怎么做”的距离。

## 2. 目标和非目标

### 2.1 目标

- 10 秒内完成一次捕获，不被表单打断；
- 原始内容始终可找回、可核对；
- 自然语言变成可执行事项，但不在不确定时冒险判断；
- 事项在合适的时间、场景或复盘周期重新出现；
- 复杂事项可得到简短方法、清单或建议；
- 用户能理解系统做了什么并修正、撤销；
- 以用户明确声明的作息、场景和偏好改善提醒，不默默建立人格档案。

### 2.2 非目标

- 自动发送消息、提交表单、下单或做外部动作；
- 自动读取全部聊天、邮件或日历；
- 后台持续定位；
- 复杂多人协作、甘特图、团队看板；
- 用完成率、积分或连续天数评价用户；
- 未经确认的医疗、财务、宗教、健康和人格推断；
- 把模型知识描述为已联网核验。

## 3. 用户和场景

第一目标用户是希望把工作、生活、家庭和个人事项放在一个可信空间中，但不愿维护复杂任务系统的个人用户。

| 场景 | 用户输入 | 系统结果 |
| --- | --- | --- |
| 突然想到 | 周五要给妈妈买药 | 保存并识别人物、动作、时间 |
| 说不清 | 上传一张聊天截图 | 保留图片并进入待确认 |
| 追加信息 | 刚才那个会议改到下午三点 | 生成补充建议，展示差异 |
| 请求帮助 | 查做披萨的材料，附在购物事项下 | 生成建议，不生成查资料任务 |
| 到时间处理 | 今天 18:30 提醒我提交报销 | 安排精确提醒和通知 |
| 没有时间 | 以后想学摄影 | 进入稍后并按节奏复盘 |
| 依赖外部 | 等客户回复后再改方案 | 进入等待中，记录等待条件 |
| 长期保留 | 保存做法和清单 | 进入独立笔记本 |

## 4. 领域对象

| 对象 | 定义 | 生命周期 |
| --- | --- | --- |
| Capture | 一次原始文字、链接、图片或混合输入，不可被 AI 覆盖 | saved → processing → processed / failed |
| Item | 可执行事项或用户确认后的记录 | proposed → scheduled / doing / waiting / later → completed / abandoned |
| Trigger | 让 Item 重新出现的时间、复盘、场景或等待条件 | active → fired / paused / canceled |
| Reminder | Trigger 产生的具体触达记录 | created → sent / failed / handled |
| Feedback | 修改、确认、撤销、延后和提醒评价 | append-only |
| Enrichment | 附着在 Item 上的建议、方法、清单 | pending → ready / failed / deleted |
| NotebookNote | 独立长期笔记，可来自建议或手写 | active → edited / deleted |
| Topic | 项目或长期主题 | active → archived |
| Category | 工作、生活、购物、人际、个人、其他 | fixed taxonomy |
| ContextFact | 用户声明或确认的作息、人物、场景、规则、偏好 | proposed → confirmed → expired / revoked |

## 5. 功能需求

优先级：P0 首发必需，P1 首发后短期必需，P2 中长期能力。

### FR-01 快速捕获（P0）

1. 首页和话题页提供唯一主捕获入口。
2. 支持文字、粘贴文字、链接、拖入 / 粘贴图片和本地图片。
3. 单次输入支持文字 + 图片混合；大小、格式和错误原因清楚可见。
4. 提交先持久化 Capture，立即返回 captureId 和已保存状态，不等待 AI。
5. 客户端生成幂等键，同一用户重复提交不得产生重复 Capture / Item。
6. 用户可以立即离开，回来后看到处理结果或失败恢复。
7. Capture 原文、链接、附件、时间、设备和处理状态可查询。

验收：网络慢或 AI 不可用时，1 秒内看到已保存；刷新后仍能找到原始输入。

### FR-02 识别和分类（P0）

系统识别：

- 任务 / 信息 / 建议请求 / 仅存档；
- 主要动作和用户责任；
- 标题、备注、分类、优先级、预计时长、精力；
- 时间点、时间窗口、人物、地点、场景、等待条件；
- 置信度、待确认字段、用户可读解释；
- 话题和归属来源：手动、AI、名称匹配或未归类。

AI 超时、无 Key、额度不足或返回错误时使用本地规则，并明确标记本地整理。

### FR-03 新建、补充、建议（P0）

- 新建：不是同一件事，创建独立 Item；
- 补充：增加原事项的时间、人物、地点、备注或事实；
- 建议：生成 Enrichment，不创建查找方法待办。

合并规则：

- 主题相似不能单独作为合并依据；
- AI 只能从服务端候选中选择目标；
- 默认创建合并建议，展示目标、字段差异和来源；
- 用户确认后才写入当前 Item；10 分钟内可撤销，历史版本始终可恢复；
- 用户手动指定话题或未归类时，后续 AI 不得改变归属；
- 撤销不删除 Capture。

### FR-04 待确认（P0）

负责人、时间、动作或截图含义有关键歧义时，Item 进入待确认。

- 一次只问一个最关键问题；
- 未回答也不丢弃原始输入；
- 可修改标题、时间、分类、话题和负责人；
- 保存后记录修改前后值；
- 可选择先保留、不再询问或转为仅存档。

### FR-05 今日工作台（P0）

提供日期、轻问候、开放数量、快速捕获和五组内容：

- 要紧；
- 进行中；
- 顺手；
- 重新想起；
- 待确认。

重新想起默认最多主动展示 3 件，用户处理后再补位。今日为空时用“今天暂时没有催促你的事。没有事情，也很好。”，不制造焦虑。

### FR-06 稍后、等待和状态（P0）

状态与出现时间独立存储：

| 动作 | 状态 | Trigger |
| --- | --- | --- |
| 今天做 | doing | 清除当前触发，进入今日 |
| 安排时间 | scheduled | 新建或替换精确时间 |
| 继续放着 | later / 保持 scheduled | 无时间按 1 → 3 → 7 → 14 → 30 天复盘，有时间保留 |
| 等待中 | waiting | 暂停主动复盘，保存等待条件和可选检查时间 |
| 完成 | completed | 停用全部触发 |
| 不再处理 | abandoned | 停用全部触发，保留历史 |

移动端提供 1 小时、今晚、明天、周末、自定义时间。

### FR-07 提醒和触达（P0）

支持精确时间、时间窗口、复盘、等待检查、用户声明的场景和每日 / 每周摘要。后台记录 Evaluated、Eligible、Sent、Failed、Handled，保证去重和可诊断。

提醒至少包含：

~~~text
现在适合处理：提交报销
为什么现在：你昨天确认已经收到发票，预计需要 10 分钟
来源：8 月 26 日上传的聊天截图
操作：今天做 · 延后 · 安排时间 · 不再处理
~~~

用户应能查看通知权限、设备、订阅、勿扰、最近投递和失败原因。

### FR-08 事项详情和来源（P0）

详情显示标题、备注、状态、时间、分类、话题、人物、场景、为什么现在出现、全部 Capture 时间线、原文、链接、图片、AI 版本、置信度、合并理由、用户修订、建议历史和关联笔记。

### FR-09 建议便笺（P0）

用户可主动请求建议。建议只直接帮助当前事项；简单琐事默认不扩写。每条显示生成来源、时间和是否联网核验。支持再次生成、删除、复制到笔记本，删除不影响 Capture、Item 和笔记副本，多条建议可查看。

### FR-10 话题和分类（P0）

- 支持手动和自然语言创建话题；
- 话题名称按用户去重，可编辑、归档；
- 一个 Item 最多一个 Topic，也可未归类；
- 分类固定为工作、生活、购物、人际、个人、其他；
- 分类跨话题聚合；
- 手动归属优先；
- 归档话题不删除事项和来源。

### FR-11 笔记本（P0）

支持手动 Markdown / 富文本笔记、标题自动生成、全文搜索、展开、编辑、二次确认删除。建议复制的笔记记录来源 Item 和 Enrichment，但独立编辑和保留。

### FR-12 账号和隐私（P0）

所有业务数据、附件、来源、话题、笔记、上下文和订阅按用户隔离。密码不明文保存；会话使用 HttpOnly、SameSite=Lax，公网 HTTPS 开启 Secure。AI 只接收当前用户的最小相关上下文。敏感内容默认只保存和提醒，不自动执行。

### FR-13 个人上下文（P1）

支持用户主动声明起床、工作、通勤、睡眠、勿扰、家 / 公司 / 电脑 / 电话 / 出门 / 回家场景、常用窗口、工作日 / 周末、少量人物关系和确认规则。

每条 ContextFact 显示来源、是否用户声明、创建和最后确认时间、适用范围、敏感等级、失效和删除入口。AI 发现的规律只能作为待确认建议。

### FR-14 搜索、历史和导出（P1）

全局搜索 Item、备注、来源、话题、分类和笔记；按开放、完成、放弃、Capture、笔记过滤；支持跳转详情、导出 JSON / Markdown / 附件清单、归档和未来的账号删除前导出。

## 6. 状态模型

~~~text
Capture
  saved → processing → processed
                    └→ failed → retry / manual resolve

Item
  proposed → needs_confirmation → scheduled / doing / waiting / later
                                     └→ completed / abandoned

Trigger
  active → eligible → fired → handled
    └→ paused / canceled
~~~

约束：完成 / 放弃只停用触发；进行中不被普通复盘推送；等待中可恢复；合并不删除 Capture；Enrichment 和 NotebookNote 不改变 Item 状态。

## 7. 非功能需求

### 性能和可靠性

- Capture 保存 P95 ≤ 1 秒，不等待模型；
- 今日首屏 P95 ≤ 2 秒；
- 常规操作反馈 ≤ 300ms；
- 首发支持每用户 10,000 个 Item、20,000 个 Capture、5,000 条笔记；
- 使用分页 / 游标；
- Job 可重试，通知有退避、去重和死信；
- 数据库、附件和迁移有备份 / 回滚；
- AI、队列、通知、数据库错误可诊断。

### 安全、隐私、可访问性

- 任意用户输入和模型输出都视为数据，不是系统指令；
- 附件限制大小、MIME、路径和下载响应头；
- 日志脱敏，不记录原文、图片、密码和 API Key；
- 触控目标 ≥ 44×44px；
- 键盘可完成主要流程，状态不只依赖颜色；
- 支持 reduced motion、深浅主题、320px 和本地时区。

## 8. 指标

- 首次捕获耗时和成功率；
- 保存后转为可处理 Item 的比例；
- AI 解析无需修改比例；
- 合并确认、撤销和改写比例；
- 提醒完成、延后、忽略和放弃比例；
- 30 天内被处理或明确放弃的复盘事项；
- 用户主动回到来源和建议的比例；
- 重复记录是否下降；
- “提醒打扰 / 时间不合适 / 解析错误”的反馈原因。

不把每天完成量作为单一北极星指标。

## 9. 分期

### P0 可信捕获和可撤销执行

异步 Capture、任务 / 信息判定、今日 / 稍后 / 等待、合并建议、来源时间线、精确 / 复盘提醒、认证隔离、话题、分类、笔记本。

### P1 可解释的个人化

上下文设置、通知中心、全局搜索、历史、建议历史、导出、归档和数据治理。

### P2 生活规划和外部连接

只读日历、可用时间推荐、关系前汇总、授权后的地点触发、带来源的实时检索、确认后的长期规律建议。
