# 安放重开发 UI / UX 说明文档

版本：1.0

状态：视觉与交互基线

## 1. 设计方向

安放不是“控制更多任务”，而是给暂时无法处理的念头一个可信容器。界面应让用户感到：内容被接住了，系统在安静工作，今天不需要被塞满。

继承现有方向：

- 品牌名“安放”和 LIFE NAVIGATOR；
- 浅色自然绿灰和深色“夜航”主题；
- 深绿、灰白、青色、荧光黄绿作为功能信号；
- 登录页“纸片落入石钵”表达容纳、安置和回归；
- 细边框、低阴影、少量网格、等宽小标签形成生活控制台气质；
- 动效只服务捕获折叠、事项展开和提醒出现。

设计取舍：把纸张、石材和夜航仪表转成界面语言。卡片像可移动的纸片，容器像安静的石面；等宽字体只用于日期、状态和系统信息，不让界面变成开发工具。

## 2. UX 原则

1. 输入优先：首页第一注意力永远是想到的事，先放在这里。
2. 系统负责整理：捕获时不要求填写复杂字段。
3. 结果可解释：告诉用户做了什么、为什么现在出现、依据哪条来源。
4. 不确定时只问一个关键问题。
5. 复杂度逐层展开：卡片最小可行动，详情完整透明。
6. 行动有后悔药：合并、删除、改时间和结束事项可撤销或恢复。
7. 不制造压力：不用红色倒计时、连续打卡、完成率排名和落后语言。
8. 隐私可见：个人上下文和 AI 使用可查看、禁用、删除。

## 3. 信息架构

### 桌面

左侧固定 Rail：

~~~text
安放
  今日                 今日注意力
  稍后                 不必现在处理
  话题                 项目和长期主题
  笔记                 值得留下的内容

────────────────
AI 状态 / 刷新 / 主题 / 账号 / 通知
~~~

### 移动

顶部保留品牌、测试环境标识和必要快捷操作；底部固定今日、稍后、话题、笔记。捕获入口不成为第五个页面，避免用户先去“记录页”再记录。

全局入口：

- 通知：权限、订阅、最近投递；
- 账号：安全、上下文、数据和隐私；
- 搜索：顶部或 ⌘ / Ctrl + K；
- 捕获：⌘ / Ctrl + Enter 提交，Esc 收起浮层。

## 4. 页面规格

### 4.1 登录 / 注册

目的：进入私人空间，而不是完成传统 SaaS 注册。

- 桌面左侧展示纸片入石钵图像，移动端缩为顶部视觉带；
- 登录文案“回到你的安放之处”，注册文案“给自己留一处安放”；
- 只保留用户名、密码、确认密码和记住登录；
- 错误显示在字段附近，登录失败不泄露用户是否存在；
- 注册时提前说明密码规则；
- 移动输入控件至少 16px，避免 iOS 自动放大；
- 深色主题中图像、文字、边界仍可辨识。

### 4.2 今日工作台

~~~text
日期 / 轻问候                         在眼前 X · 替你记着 Y

┌─────────────────────────────────────────┐
│ 随手安放                                  │
│ 想到的事，先放在这里……                    │
│ [截图] [话题]              [安放 ⌘↵]       │
└─────────────────────────────────────────┘

[要紧 2] [进行中 1] [顺手 3] [重新想起 2] [待确认 1]

事项列表
~~~

要求：

- 首屏突出捕获和今天真正要看的事；
- 只显示有内容的分组；
- 重新想起使用“由你决定下一步”，不用逾期；
- 首次加载使用骨架或温和加载文字；
- 空状态：“今天暂时没有催促你的事。想到什么就放在上面。没有事情，也很好。”

### 4.3 捕获组件

初始态：

- 大文本输入区和左侧容器标记；
- 截图、话题选择、安放按钮；
- 粘贴 / 选择图片后显示缩略图和移除；
- 说明支持文字、链接和粘贴图片。

状态：

- 保存中：按钮显示正在保存，输入不丢失，禁止重复提交；
- AI 处理中：捕获框缩为紧凑条，可继续浏览；
- 正常：已安放：提交报销；
- 降级：已保存，先用本地规则整理；
- 待确认：已保存，需要你确认一件事；
- 失败：原始内容已保留，整理没有完成 + 重试 / 手动处理；
- 合并：发现可能是同一件事 + 目标和差异确认。

### 4.4 事项卡

~~~text
[完成圆钮] 标题                         [更多]
            状态 · 时间 · 分类 · 话题
            人物 / 场景 / 时长 / 来源数量
            [建议便笺预览]
            [下一步：今天做 / 安排时间 / ...]
~~~

- 点击标题轻量改名，不影响时间、分类、话题和状态；
- 点击时间打开安排出现时间面板，提供今晚 / 明天 / 周末快捷项；
- 分类和话题是可点击入口；
- 更多操作进入 Popover 或详情抽屉；
- 完成后显示可撤销 Toast；
- 不再处理用警示色并二次确认；
- 优先级同时用文字、排序或小标记表达，不能只靠颜色。

### 4.5 事项详情

重开发必须增加事项详情，用来补齐当前数据库有来源但用户看不到的问题。

桌面用右侧 480–560px 抽屉，移动端用全屏页面。内容：

1. 标题、状态、时间、优先级、分类、话题；
2. 为什么现在出现；
3. 下一步操作；
4. 建议便笺历史；
5. Capture 来源时间线：原文、链接、图片和每次补充；
6. AI 模型、版本、置信度和解释；
7. 用户修改历史、差异和撤销；
8. 归档 / 不再处理 / 删除。

### 4.6 待确认和合并确认

待确认用黄色 / 青色边框，不用错误红色：

~~~text
需要你确认一下
这张截图中需要你做什么？
[截图]
[标题输入]
什么时候再出现 [时间选择]
[保存] [先放着]
~~~

合并确认：

~~~text
可能是同一件事
你刚记录：下午的高铁时间是 17:58
将补充到：去虹桥
会改变：时间、备注
不会改变：来源、话题、完成状态
[补充到这件事] [作为新事项]
~~~

### 4.7 稍后

口吻是“已经替你收好”，不是“逾期仓库”。分组为等待中、已有安排、暂未安排、待确认。每张复盘卡提供今天做、安排时间、继续放着、等待中、不再处理；移动端主要动作置顶，按钮两列或单列。

### 4.8 话题和分类

话题首页用卡片网格显示名称、描述、待处理、已完成数量。详情页顶部返回，显示名称 / 描述 / 编辑、专属捕获框、待处理 / 已完成。分类合集跨话题聚合，并说明“分类是这是什么事，话题是属于哪个项目”。

### 4.9 笔记本

顶部使用“值得留下的内容”，副文案说明笔记不会催促用户。笔记默认折叠显示日期、标题、摘要；展开后显示正文、来源事项、编辑和删除。搜索高亮命中词并显示数量。删除需二次确认，并说明原事项建议不受影响。

### 4.10 设置和隐私

当前账号页只有改密和退出，重开发扩展为：

- 账号与会话；
- 通知权限、设备、勿扰和测试提醒；
- 作息、工作日和常用时间窗口；
- 场景、人物、个人规则；
- AI 与数据发送说明；
- 导出、附件管理、归档和删除。

上下文标记为用户声明、AI 建议待确认、已确认、已过期；删除入口不能藏在难找的菜单中。

## 5. 视觉系统

### 5.1 浅色 Token

| Token | 用途 | 值 |
| --- | --- | --- |
| canvas | 页面底色 | #F6F7F2 |
| rail | 导航 / 顶栏 | #EEF1E9 |
| panel | 卡片 / 浮层 | #FFFFFF |
| panel-raised | 事项背景 | #FBFCF8 |
| text | 主要文字 | #24352C |
| text-soft | 次主要文字 | #526057 |
| muted | 辅助文字 | #606D63 |
| line | 分隔线 | #DCE3D9 |
| signal | 主行动 | #42654F |
| cyan | 时间 / 建议 | #276B65 |
| danger | 错误 / 结束 | #AB4C39 |

### 5.2 夜航主题

| Token | 值 |
| --- | --- |
| canvas | #080D18 |
| rail | #0B111E |
| panel | #101827 |
| text | #F2F5EE |
| signal | #D9FF68 |
| cyan | #72E6D1 |
| danger | #FF8066 |

语义：signal 用于安放、确认、完成；cyan 用于时间、等待、建议；danger 只用于删除、放弃、失败。

### 5.3 字体、尺寸和阴影

- 中文正文使用 PingFang SC / Hiragino Sans GB 等系统无衬线；
- 英文品牌使用 Avenir Next 或同等人文无衬线；
- 时间、状态、模型、环境使用 SF Mono / Consolas；
- 登录少量情绪标题可用宋体；
- 正文 14–16px，移动输入至少 16px；
- 基础间距 4px，常用 8 / 12 / 16 / 24 / 32 / 48 / 64px；
- 卡片 6–8px 圆角，边框优先于厚重阴影；
- 内容最大宽度 1120px，阅读型内容 720–880px；
- 所有交互热区至少 44×44px。

## 6. 响应式

| 宽度 | 规格 |
| --- | --- |
| ≥1200px | 左 Rail + 1120px 主内容 + 桌面详情抽屉 |
| 900–1199px | 收窄 Rail，减少左右内边距 |
| 600–899px | 顶部栏、单列、底部导航 |
| 320–599px | 单列、详情全屏、隐藏次要说明 |

移动端：顶部 64–70px，底部适配 safe area；捕获浮层边距 10–14px；事项不使用 hover 位移；动作按钮高度至少 36px；话题卡一列；日期选择提供快捷时间。

## 7. 状态、动效和文案

每个组件定义 default、hover、focus-visible、pressed、disabled、loading、success、error、empty、permission denied、offline / retry。

- Toast 用于成功和低风险变更，3–4 秒消失；
- 错误、待确认和模型失败同时在组件附近显示；
- 成功提示带撤销，例如“已完成，撤销”；
- 捕获折叠 300–450ms，详情展开 150–220ms；
- 不使用闪烁、持续呼吸、无限滚动；
- reduced motion 时取消位移和弹簧。

推荐用词：

~~~text
已保存，正在整理
原始内容已保留，整理没有完成
需要你确认一下
发现可能是同一件事
这条建议基于模型知识生成，未联网核验
今天暂时没有催促你的事
没有事情，也很好
~~~

避免“你落后了”“逾期 X 天”“完成率只有 X%”“必须马上处理”。

## 8. 可访问性

- 每页唯一 h1，事项使用 h3 / h4；
- 今日 tab 支持方向键、Home、End；
- 图标按钮有 aria-label，状态不只依靠颜色；
- 错误与输入关联 aria-describedby，提交失败焦点到错误字段；
- 抽屉 / Dialog 管理焦点，Esc 关闭，关闭后回到触发按钮；
- 图片 alt 描述上下文，装饰图标 aria-hidden；
- Markdown 链接、表格、复选框可键盘操作；
- 主题、通知和测试环境标识不阻断捕获。

## 9. UX 验收场景

1. 新用户 3 秒内找到捕获入口；
2. 粘贴截图后离开再回来，仍可看到状态或失败恢复；
3. 合并确认能看懂目标、差异和新建选项；
4. 详情能找到最初文字、截图和所有补充；
5. 完成后能撤销；
6. 继续放着后能看到下一次复盘时间；
7. 点击通知进入对应事项；
8. 删除建议时知道原始 Capture 和笔记副本不受影响；
9. 上下文页面区分用户声明和 AI 建议；
10. 320px 无横向滚动；
11. 键盘可完成主要流程；
12. 深浅主题下文字、边框和焦点仍清楚。

## 10. 设计交付物

- 登录、今日、Capture 处理、详情、稍后、话题、分类、笔记、设置线框；
- Token 表、主题变量和组件状态矩阵；
- 合并、待确认、删除、撤销和失败恢复交互稿；
- 320px、390px、桌面关键页面；
- 真实中文样例；
- 无障碍焦点顺序和快捷键；
- 设计验收截图和浏览器回归清单。
