# 标题编辑与分类合集

## 两种整理维度

- **分类**回答“这是什么类型的事”：工作、生活、购物、人际、个人、其他。AI 识别，未配置 AI 时使用本地规则，每件事只有一个分类。
- **话题**回答“这件事属于哪个具体项目”：例如官网改版、搬家计划。话题可以新建、命名和描述。
- 分类与话题互相独立。例如“为发布会购买饮料”可以同时属于“购物”分类和“新品发布会”话题。购物合集会包含不同话题和未归入话题的所有购物事项。

过去卡片上的“购物”“工作”有时只是自由生成的场景提示。现在使用已有的结构化分类作为可点击入口，不再重复显示同名场景文字；“外出购物”“下班后”等更具体的场景仍作为提示保留。

## 如何使用

1. 点击事项标题或旁边的小铅笔，输入新标题后点“保存标题”。取消不会修改任何数据；标题不能为空，最多 120 个字。
2. 单独改标题不会更改提醒时间（包括秒）、待确认状态、分类、话题或完成状态。已完成事项也可改名，但不会重新进入待办。
3. 点击事项上的“购物”“工作”等分类标签，即可进入对应合集；“话题”首页的“按分类查看”也提供所有分类入口。
4. 合集展示待处理和已完成两组；已合并和不再处理的事项不计入。分类入口的数字只代表待处理数量，不复制任务。
5. 分类识别不合适时，展开事项“更多操作”，调整“所属分类”。后续 AI 补充同一事项时会保留手动选择。话题、提醒、来源、建议和笔记副本不受影响。
6. 合集内可以继续改标题、改时间、完成事项、查看建议；点击话题标签可进入项目，返回按钮可回到原来的今日、稍后或话题页面。

当前分类使用上述六个固定类型，不支持自定义分类名称；具体项目和自定义组织需求继续使用话题。没有额外增加手机底部导航。

## 实现与兼容

- 继续使用已有的 `items.category`，只新增 `category_manual` 标记（旧数据默认 0）及分类索引，不复制已有记录、不迁移分类名称。
- `PATCH /api/items/:id` 新增 `rename` 与 `set_category` 动作，并保留反馈记录。
- `GET /api/categories/:id` 返回分类信息、计数和事项；`GET /api/dashboard` 增加六类摘要。
- 原始输入与笔记本副本保持独立，改事项标题不会重写原始记录或笔记标题。
- 新增接口回归覆盖标题校验、精确时间保留、完成和等待状态、跨话题合集、无重复计数、空合集、手动分类以及 AI 补充后的归类保持。
