# “稍后”与任务状态

## 设计原则

“任务做到哪一步”和“什么时候重新看见它”是两件事，系统分别保存：

- **状态**回答现在是什么情况：新任务、进行中、等待中、已完成；
- **出现时间**回答它什么时候回到眼前：用户安排的精确时间，或系统安排的复盘时间。

因此，“稍后”不是终态，也不是一个会越堆越满的仓库。它只是暂时不占用今日注意力的地方。

## 用户看到的状态

| 状态 | 含义 | 在哪里出现 |
| --- | --- | --- |
| 新任务 | 尚未开始 | 今日到期、重新想起，或稍后 |
| 进行中 | 已决定今天推进 | 今日的“正在做” |
| 等待中 | 正在等别人、材料或条件 | 稍后的“等待中” |
| 已完成 | 已经处理完 | 话题或分类的已完成列表 |

“不再处理”会结束事项并移出所有待处理列表；它不是日常需要反复展示的工作状态。

## 稍后事项怎样回来

### 有明确时间

事项按照用户设置的精确时间回到今日，并由提醒调度器发送通知。点击“继续放着”不会修改这个时间。

### 没有明确时间

系统设置一个复盘时间。默认间隔按优先级决定：

- 紧急：立即进入“重新想起”；
- 高：1 天后；
- 普通：3 天后；
- 低：7 天后。

到达复盘时间后，事项进入今日的“重新想起”，每次最多展示 3 件，避免一次把积压全部倒给用户。用户选择“继续放着”时，间隔逐步变为 3、7、14、30 天，最长保持 30 天。

已有旧“稍后”事项升级时会分散到 3 天内开始第一轮复盘，避免同一天全部出现。

## 五个决定

“重新想起”、稍后和等待中的事项提供五个明确动作：

1. **今天做**：变为进行中，移到今日；
2. **安排时间**：设置或修改精确出现时间；
3. **继续放着**：保留精确时间，或拉长无时间事项的复盘间隔；
4. **等待中**：暂停主动复盘，表示在等外部条件；
5. **不再处理**：结束事项，不再提醒。

用户没有立刻决定时，已经进入“重新想起”的事项会留在今日，直到做出选择；处理一件后，下一件已到期事项才有机会进入最多三件的展示额度。

## 当前 MVP 边界

- 等待中事项暂时由用户主动恢复，自动追问等待结果留到下一阶段；
- 复盘间隔目前使用固定规则，后续可依据用户实际的延期与完成反馈个性化；
- “进行中”表示今天已开始，不包含复杂的项目进度、多人分工或看板流程。
